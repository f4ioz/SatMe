## Prochaine version

### fr
- **Publication web : SatMe-PC envoie vers un site web extérieur**, quel qu'il soit (module facultatif, désactivé d'origine, qu'aucun profil n'active ; *Réglages › Modules*). Tant qu'il est décoché, rien ne part (ni file, ni essai, ni direct) et aucun bouton 🌐 n'apparaît. Coché, *Réglages › Services en ligne › Envoyer vers un site web* : SatMe-PC envoie, par HTTPS, ce que vous choisissez — images SSTV, planches, rapports, contacts, vidéos du journal — à **une adresse de votre site** (avec `{type}`, ou une seule adresse pour tout), un jeton facultatif ; votre site les reçoit comme il veut (PHP, WordPress, un petit serveur Python…). **Tester** (obligatoire : prêt seulement après un essai réussi), puis pour chaque genre **Sur clic** (d'origine), **Automatique** ou **Jamais**. Le format est une **API documentée et versionnée** (en-têtes `X-SatMe-…`, `multipart/form-data` avec une fiche JSON, un identifiant par envoi pour ne rien publier deux fois), avec des récepteurs prêts à l'emploi en PHP et en Python et une page qui affiche ce qui est reçu : voir `docs/publication-web.fr.md`. Un jeton refusé arrête tout jusqu'au prochain test ; un type refusé s'affiche « refusé (403) » dans l'historique.
- **Publication web vers un dossier** : sans serveur, SatMe-PC écrit chaque élément dans un dossier de ce PC (`type/année/id.ext` et sa fiche `.json`, un `index.json`, un flux Atom `flux.xml`, écrits sans jamais laisser un fichier à moitié), pour un site statique ou un outil de synchronisation que vous avez déjà (Nextcloud, Syncthing, miroir rsync ou FTP).
- **Windows, installateur : une mise à jour n'efface plus rien de vos fichiers.** L'installateur `satme-pc-windows.msi` vidait tout le dossier du programme en remplaçant l'ancienne version, y compris un dossier `donnees` posé à côté (mode portable). Il ne retire désormais que ses propres fichiers. **Avant d'installer celle-ci** par-dessus la 2026.10.33 ou une plus ancienne, copiez ailleurs un dossier `donnees` posé dans le dossier du programme : l'ancienne version le vide encore une dernière fois en se retirant.
- **Installé par le MSI, SatMe-PC garde ses données dans `%APPDATA%\SatMe`**, jamais dans le dossier du programme : un dossier `donnees` trouvé là est copié au démarrage dans `%APPDATA%\SatMe` (ou `%APPDATA%\SatMe-portable-<date>` s'il sert déjà), vérifié, puis utilisé ; l'original est gardé et une fenêtre dit où sont vos données. *Réglages › Démarrage* refuse un dossier des données dans celui du programme. Le mode portable reste celui du ZIP (clé USB).
- **Publication web › En direct** (facultatif, chaque partie cochée à part, rien d'origine) — **Auto-pilote** (prochain passage d'une campagne, réception en cours, prochaine image, dernière image reçue ; pendant un passage, l'image qui arrive toutes les 5 s), **Spectre QO-100** (le transpondeur étroit vu par le SDR, une ligne par seconde) et **Image DATV** (une image réduite et le MER, tant que le récepteur est verrouillé). Le site ne se connecte jamais à la station ; seulement des noms, des heures et des mesures, jamais une adresse, un code ou une clé. Pas de file : si le site ne répond pas, SatMe-PC attend et réessaie ; **Effacer le direct** le retire tout de suite. Vers un dossier : `direct/direct.json` et les images. Une station qui publiait déjà vers son site garde le module, et son adresse devient `…/api/publication/{type}`.

### en
- **Web publishing: SatMe-PC pushes to an outside web site**, whatever it is (an optional module, off by default, which no profile switches on; *Réglages › Modules*). While it is off nothing goes out (no queue, no test, no live data) and no 🌐 button shows. Ticked, *Réglages › Services en ligne › Envoyer vers un site web*: SatMe-PC sends over HTTPS what you choose — SSTV pictures, planches, reports, contacts, the journal's videos — to **an address of your site** (with `{type}`, or one address for everything), an optional token; your site receives them as it likes (PHP, WordPress, a small Python server…). **Tester** (required: ready only after a test that passes), then each kind **Sur clic** (the default), **Automatique** or **Jamais**. The format is a **documented, versioned API** (`X-SatMe-…` headers, `multipart/form-data` with a JSON card, one id per delivery so nothing is published twice), with ready-to-use receivers in PHP and Python and a page showing what was received: see `docs/publication-web.md`. A refused token stops everything until the next test; a refused kind shows « refusé (403) » in the history.
- **Web publishing to a folder**: with no server, SatMe-PC writes each item into a folder of this PC (`type/year/id.ext` and its `.json` card, an `index.json`, an Atom feed `flux.xml`, never leaving half a file), for a static site or a sync tool you already have (Nextcloud, Syncthing, an rsync or FTP mirror).
- **Windows installer: an update no longer deletes any of your files.** `satme-pc-windows.msi` emptied the whole program folder when replacing the old version, a `donnees` folder put beside it (portable mode) included. It now removes only its own files. **Before installing this one** over 2026.10.33 or older, copy a `donnees` folder kept in the program folder elsewhere: the old version still empties it one last time as it goes.
- **Installed by the MSI, SatMe-PC keeps its data in `%APPDATA%\SatMe`**, never in the program folder: a `donnees` folder found there is copied at start to `%APPDATA%\SatMe` (or `%APPDATA%\SatMe-portable-<date>` when that is in use), checked, then used; the original is kept and a window says where your data is. *Réglages › Démarrage* refuses a data folder inside the program folder. Portable mode stays the ZIP's (USB stick).
- **Web publishing › En direct** (live, optional, each part ticked on its own, nothing by default) — **Auto-pilot** (a campaign's next pass, the reception under way, the next picture, the last picture received; during a pass, the picture arriving every 5 s), **QO-100 spectrum** (the narrow band as the SDR sees it, one line a second) and **DATV picture** (a small picture and the MER while the receiver is locked). The site never connects to the station; only names, times and measurements, never an address, a code or a key. No queue: when the site does not answer, SatMe-PC waits and tries again; **« Effacer le direct »** removes it at once. To a folder: `direct/direct.json` and the pictures. A station that already published to its site keeps the module, and its address becomes `…/api/publication/{type}`.

Refus si l'horloge dérive (±0,5 s en FT4). **Mode données (USB-D)** coché d'origine : pendant l'émission armée, SatMe met l'IC-9700 en USB-D / LSB-D (les deux bandes en mode satellite, la boucle Doppler le garde), jamais pendant le PTT, et remet le mode d'avant à l'arrêt ; sur le poste, *DATA MOD* = USB. QSO fini : **Noter le QSO** préremplit le carnet (satellite, mode SAT). En démonstration : émission simulée, stations fictives qui répondent.

Globe (orbites, trace au sol vue du satellite), carte 2D, ciel du passage, globe et carte du Sked ; devant toujours vif, derrière plus pâle. Plus marquées qu'avant d'origine ; gardé dans ce navigateur.
